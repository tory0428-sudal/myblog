# 지침: 2048 게임 웹앱 계획 작성

## 배경
이 저장소는 마크다운 기반 블로그 + 미니 웹앱 포트폴리오 프로젝트다 (`/CLAUDE.md` 참고).
사용자가 "2048 게임"을 요청했다: 방향키로 숫자 타일을 밀어서 합치는 퍼즐 게임, 점수판 포함.

## 네가 할 일
`/app/2048/` 폴더에 들어갈 2048 게임 웹앱의 구현 계획을 세우고, 그 계획을 `/app/2048/spec.md` 파일로 저장한다.
**코드를 작성하지 마라. 계획만 세운다.**

## 범위 제한
- 오직 `/app/2048/spec.md` 파일만 생성/수정한다.
- 저장소의 다른 파일(index.html, css/style.css, js/* 등 블로그 파일)은 절대 건드리지 않는다.

## 제약사항 (CLAUDE.md 웹앱 규칙)
- HTML, CSS, 바닐라 JavaScript만 사용 (프레임워크 없음, 번들러 없음)
- 웹앱은 `/app/2048/` 폴더 안에서 완전히 자체 완결되어야 함 (블로그 파일에 의존하지 않음)
- 외부 라이브러리 사용 최소화, 필요하면 CDN 스크립트 허용
- 모바일에서도 사용 가능해야 함 (스와이프 등 터치 입력 고려)

## spec.md에 포함해야 할 내용
1. **게임 개요**: 2048 게임 규칙 요약 (4x4 격자, 방향키로 타일 이동/병합, 2 또는 4 타일 랜덤 생성, 승리/패배 조건)
2. **파일 구조**: `/app/2048/` 안에 들어갈 파일 목록과 각 역할 (예: index.html, style.css, game.js 등)
3. **UI 구성**: 점수판(현재 점수, 최고 점수 localStorage 저장) 위치, 게임 보드, 새 게임 버튼, 게임오버/승리 메시지 표시 방법
4. **핵심 로직 설계**: 격자 상태를 어떤 자료구조로 표현할지, 이동/병합 알고리즘 개요, 랜덤 타일 생성 로직
5. **입력 처리**: 키보드 방향키 이벤트, 모바일 터치 스와이프 이벤트
6. **다크모드**: 블로그의 다크모드 톤과 비슷하게 갈지, 독립적으로 갈지 명시 (독립 완결 원칙 유지)
7. **반응형/모바일 대응** 방안

계획은 간결하고 실행 가능하게 작성한다. 과도한 설계나 불필요한 추상화는 지양한다.
