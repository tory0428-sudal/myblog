# 지침: 2048 게임 웹앱 검증 (review)

## 배경
`/app/2048/` 폴더에 2048 게임 웹앱이 구현되어 있다 (`spec.md`가 계획, `index.html`/`style.css`/`game.js`/`input.js`/`main.js`가 구현체).
이 구현이 실제로 정상 동작하는지, 코드에 문제가 없는지 검증한다.

## 네가 할 일
1. `app/2048/spec.md`와 구현 파일들을 읽고 계획대로 구현되었는지 코드 리뷰한다.
2. 브라우저에서 실제로 게임을 실행해 동작을 검증한다:
   - 정적 서버로 `app/2048/index.html`을 서빙해서 연다 (예: 저장소 루트에서 `python -m http.server` 등으로 띄우고 `/app/2048/index.html` 경로로 접속, 또는 사용 가능한 preview 도구 사용).
   - 방향키(↑↓←→)로 타일이 실제로 밀리고 합쳐지는지 확인.
   - 점수판이 갱신되는지, 새 게임 버튼이 동작하는지 확인.
   - 최고 점수가 localStorage에 저장되고 새로고침 후에도 유지되는지 확인.
   - 콘솔 에러가 없는지 확인 (read_console_messages 등 활용).
   - 가능하면 모바일 크기(예: 375px 너비)로 리사이즈해서 레이아웃이 깨지지 않는지, 가로 스크롤이 생기지 않는지 확인.
   - 다크모드(prefers-color-scheme: dark)에서도 확인.
3. 발견한 문제를 직접 수정한다 (코드 버그, 레이아웃 깨짐, spec 대비 누락된 기능 등). 사소한 수정은 네가 바로 고쳐라.
4. 검증 결과를 `app/2048/review.md` 파일로 작성한다: 테스트한 항목, 발견한 문제와 수정 여부, 최종 상태(정상 동작 여부).

## 범위 제한 (반드시 지킬 것)
- **오직 `/app/2048/` 폴더 안의 파일만 수정한다** (버그 수정 포함).
- 블로그의 다른 파일(루트 `index.html`, `css/style.css`, `js/*.js`, `posts/*` 등)은 **절대 건드리지 않는다**.
- `spec.md`, `plan-instructions.md`, `build-instructions.md`는 수정하지 않는다 (읽기만 한다).
- `review.md`는 새로 작성한다.

## 완료 후
`review.md`의 핵심 내용(테스트 결과, 수정한 문제가 있다면 무엇인지)을 요약해서 보고해라. 만약 스스로 고칠 수 없는 심각한 문제를 발견하면, 수정하지 말고 무엇이 문제인지 명확히 보고해라 (막히면 알린다).
