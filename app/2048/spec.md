# 2048 게임 웹앱 구현 계획

## 1. 게임 개요
- 4x4 격자(16칸) 위에서 진행하는 숫자 타일 퍼즐 게임.
- 방향키(↑↓←→)를 누르면 모든 타일이 해당 방향으로 밀리며, 같은 숫자의 타일이 만나면 하나로 합쳐지고 값이 2배가 된다 (합쳐진 타일의 값만큼 점수 획득).
- 매 이동 후 빈 칸 중 하나에 새 타일이 생성된다 (90% 확률로 2, 10% 확률로 4).
- 타일이 하나라도 실제로 이동/병합되었을 때만 새 타일을 생성한다 (제자리 이동은 무효 처리).
- 승리 조건: 타일 중 하나가 2048에 도달하면 승리 메시지 표시 (계속 진행 가능하도록 "계속하기" 옵션 제공).
- 패배 조건: 격자가 가득 찼고 상하좌우 어느 방향으로도 이동/병합이 불가능하면 게임 오버.

## 2. 파일 구조
`/app/2048/` 폴더 안에 아래 파일만 생성한다 (프레임워크·번들러 없이 순수 HTML/CSS/JS):

- `index.html` — 게임 페이지 마크업 (점수판, 보드, 버튼, 안내 문구). CSS/JS를 상대경로로 로드.
- `style.css` — 레이아웃, 타일 색상, 반응형, 다크모드 스타일.
- `game.js` — 게임 상태(격자, 점수) 및 핵심 로직 (이동/병합/랜덤 생성/승패 판정).
- `input.js` — 키보드 방향키 이벤트 + 모바일 터치 스와이프 이벤트를 받아 game.js의 이동 함수를 호출.
- `main.js` — 앱 진입점: DOM 초기화, 렌더링, localStorage 최고점수 로드/저장, 새 게임 버튼 바인딩, game.js/input.js 연결.
- `spec.md` — 본 계획 문서 (이미 존재).

역할을 game.js(순수 로직) / input.js(입력) / main.js(DOM 렌더링·초기화)로 나누어 테스트와 유지보수를 쉽게 한다. 외부 라이브러리·CDN 없이 순수 바닐라 JS로 충분히 구현 가능하므로 CDN도 사용하지 않는다.

## 3. UI 구성
- 상단: 페이지 제목("2048") + 간단한 설명 한 줄.
- 그 아래 점수판(가로 정렬 2개 박스):
  - "SCORE" 박스: 현재 점수 표시.
  - "BEST" 박스: 최고 점수 표시, `localStorage`(key: `2048-best-score`)에서 불러오고 현재 점수가 갱신될 때마다 저장.
- 점수판 옆/아래에 "새 게임" 버튼 (클릭 시 격자 초기화, 점수 0, 새 타일 2개 생성).
- 게임 보드: 4x4 grid, 각 칸은 `div.tile` 또는 빈 칸. 타일 값에 따라 배경색이 달라짐 (CSS 클래스 `tile-2`, `tile-4`, `tile-8`... 방식).
- 게임오버/승리 메시지: 보드 위에 반투명 오버레이(`.game-overlay`)로 표시. "You Win!" 또는 "Game Over" 텍스트 + "다시 시작" 버튼. 승리 시에는 "계속하기" 버튼도 추가로 노출해 오버레이를 닫고 게임 계속 진행 가능하게 한다.
- 하단: 방향키 또는 스와이프로 조작하라는 짧은 안내문.

## 4. 핵심 로직 설계 (game.js)
- 격자 상태: `board = number[4][4]` 형태의 2차원 배열, 빈 칸은 `0`으로 표현.
- 이동 알고리즘 개요 (4방향 공통 로직을 재사용):
  1. 각 방향을 "왼쪽으로 밀기" 기준 연산으로 통일하기 위해, 위/아래/오른쪽 이동 시에는 보드를 회전(또는 전치+반전)한 뒤 왼쪽 이동 로직을 적용하고 다시 역회전한다.
  2. 왼쪽 이동 로직(행 단위 처리):
     - 각 행에서 0을 제거해 값들을 왼쪽으로 압축.
     - 압축된 값들을 왼쪽부터 순회하며 인접한 두 값이 같으면 병합(값*2, 점수에 더함), 병합된 타일은 같은 턴에 다시 병합되지 않도록 플래그 처리.
     - 병합 후 다시 0을 제거해 압축.
     - 4칸이 되도록 남은 칸에 0 채움.
  3. 이동 전/후 보드를 비교해 변화가 있었는지(`moved: boolean`) 판정 — 변화가 없으면 새 타일 생성 생략.
- 랜덤 타일 생성 로직: 빈 칸(`value === 0`) 좌표 목록을 만들고, 그 중 무작위 하나를 선택해 90% 확률로 2, 10% 확률로 4를 배치.
- 승리 판정: 이동/병합 처리 중 결과값이 2048 이상이 되는 순간 플래그 설정(단, 최초 1회만 승리 오버레이 표시).
- 패배 판정: 보드가 가득 찼을 때, 4방향 각각에 대해 "이동 가능 여부(=인접 동일값 존재 여부 포함)"를 시뮬레이션해서 하나도 불가능하면 게임 오버.
- 상태 객체 예시: `{ board, score, best, isGameOver, hasWon }` 를 game.js가 관리하고, main.js는 이 상태를 읽어 렌더링만 담당 (관심사 분리).

## 5. 입력 처리 (input.js)
- 키보드: `document.addEventListener('keydown', ...)` 로 `ArrowUp/Down/Left/Right` 감지, 대응하는 이동 함수 호출 후 `preventDefault()`로 스크롤 방지.
- 모바일 터치 스와이프: 보드 요소에 `touchstart`/`touchend` 리스너를 달아 시작/종료 좌표 차이를 계산.
  - `deltaX`, `deltaY` 절댓값을 비교해 더 큰 축을 스와이프 방향으로 판정.
  - 최소 스와이프 거리(예: 20px) 미만은 무시(오조작 방지).
  - `touchmove`에서 `preventDefault()`로 페이지 스크롤/바운스 방지 (보드 영역에 한해).
- 두 입력 모두 동일한 `handleMove(direction)` 콜백을 호출하도록 통일해 game.js 로직을 공유.

## 6. 다크모드
- 블로그(`css/style.css`)와 완전히 동일한 CSS 변수를 import/공유하지 않는다 (자체 완결 원칙 유지, `/app/2048/`는 블로그 파일에 의존하지 않음).
- 다만 시각적 톤은 유사하게 맞춘다: `style.css` 자체에 블로그와 비슷한 뉴트럴 배경/전경 팔레트를 독립적으로 정의.
  - `@media (prefers-color-scheme: dark)` 만 사용해 시스템 설정을 따르는 자동 다크모드로 구현한다 (별도 토글 버튼 없이 최소 구현; 토글이 필요하면 향후 확장 여지로 `data-theme` 속성 방식을 남겨둔다).
  - 라이트: 밝은 배경(`#faf8ef` 계열, 2048 원작과 유사) / 다크: 어두운 배경(`#1a1a1a`~`#202225` 계열), 타일 색상은 값별로 별도 팔레트를 유지하되 다크모드에서도 대비가 충분하도록 조정.
- 타일 색상 자체(2/4/8/16...)는 다크/라이트 공통으로 고정하거나, 다크모드에서 살짝 채도를 낮추는 정도로만 조정 (원작 2048의 정체성 유지).

## 7. 반응형/모바일 대응
- 보드 크기는 `vw` 기반 또는 `max-width` + `aspect-ratio: 1/1` 로 정사각형 유지, 화면 폭에 따라 유동적으로 축소.
- 뷰포트 메타 태그(`width=device-width, initial-scale=1`) 필수 포함.
- 타일 폰트 크기는 타일 크기에 비례하도록 `clamp()` 등 뷰포트 단위 사용.
- 터치 타깃(새 게임 버튼 등)은 최소 44x44px 확보.
- 좁은 화면에서 점수판과 보드가 세로로 자연스럽게 쌓이도록 flex-column 레이아웃 사용, `max-width: 480px` 컨테이너로 모바일/데스크톱 공통 레이아웃 단순화.
- 터치 스와이프 시 브라우저 기본 제스처(뒤로가기 스와이프, 스크롤, 확대)와 충돌하지 않도록 보드 영역에 `touch-action: none` 적용.

## 구현 순서 제안 (build 단계 참고용)
1. `index.html` 뼈대 + `style.css` 레이아웃/다크모드 (정적 UI 먼저 확인)
2. `game.js` 순수 로직 (보드 초기화, 이동/병합, 랜덤 생성, 승패 판정) — 콘솔로 단독 검증 가능하게 작성
3. `main.js` 렌더링 연결 + localStorage 최고점수
4. `input.js` 키보드 + 터치 스와이프 연결
5. 반응형/다크모드 최종 점검
